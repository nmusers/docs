#+title: 1. Introduction

* Introduction
NM-TRAN stands for NONMEM Translator, a FORTRAN 90/95 library that
preprocesses user inputs before a NONMEM run. It converts them into
three things: a /NONMEM data set/, a /NONMEM control stream/ [fn:1], and needed subroutines.


** What it does

NM-TRAN takes a flexible input data set and turns it into a proper
NONMEM data set. It also takes a user-friendly NM-TRAN control stream and translates it into a NONMEM control stream.

Optionally, it generates full FORTRAN subroutines from abbreviated
code—like a PRED routine that handles model derivatives automatically
via symbolic differentiation. This makes models easier to write with
explicit mixed effects model parameters.


** Who should use it

Though NONMEM input can be done without NM-TRAN, most models,
including those in the NONMEM Documentation. We recommend it to all NONMEM
users.


** Example

Feed NM-TRAN a data set (e.g., THEO) and control stream like this simplified one:
#+begin_src php
$PROB THEOPHYLLINE POPULATION DATA
$INPUT ID DOSE TIME CP=DV WT
$DATA THEO

$PRED
; Model equations here (KA, KE, CL, etc.)
IF (DOSE.NE.0) THEN
   DS=DOSE*WT
   W=WT
ENDIF
; ... (full model)

$THETA (.1,3,5) (.008,.08,.5) (.004,.04,.9)
$OMEGA BLOCK(3) ...
$SIGMA .4

$EST MAXEVAL=450 PRINT=5
$COV
$TABLE ID DOSE WT TIME
#+end_src

NM-TRAN outputs ready-to-run NONMEM files, matching analyses like Guide I's theophylline example.

** Input and output files
NM-TRAN takes its input from two files:
- NM-TRAN control stream,
- NM-TRAN data set.

The first file uses control record entry $DATA to specify the path to the second.

NM-TRAN modifies (see
next section) its data file input and generates the data file FDATA
for NONMEM [fn:2]. This FDATA file is among the several NM-TRAN output
files, including
| FILE    | Content                        | Usage            |
|---------+--------------------------------+------------------|
| FDATA   | NONMEM data set                | NONMEM input     |
| FCON    | NONMEM control stream          | NONMEM input     |
| FSUBS   | generated and user subroutines | build executible |
| FSTREAM | NONMEM file stream             | NONMEM input     |
| FREPORT | report file                    | Informational    |

See @@html:<a href="/reference-manual/files/">reference manual</a>@@ for additional
files and details.

NONMEM consumes the input files created by NM-TRAN, and generates  a number of files during the run.

If an Model Specification File (MSF) is output, and intermediate output with iteration summaries
is requested (i.e., $ESTIM options MSFI and PRINT are used), then
NONMEM also writes the parameter estimates of these summaries to
the console and to file INTER, which now exists after the run
terminates.  INTER now include lines giving the parameter  estimates
in their natural unscaled space  (NPARAMETR) as well as the UCP
values (PARAMETER).

Additional output files include
files with  extensions  (suffixes)  .ext,  .cov,  .coi,
 .cor,  .phi,  .phm,  .grd,  .shk,  .shm, .cnv, smt, .rmt, etc.
The names of the files start with "root", where root is the root name of the NM-TRAN control stream file.
The file root.ext is called the raw output file.
The root name may be specified by $ESTIMATION record option FILE.


[fn:1] Before NM-TRAN was developed NONMEM requires input files in a
less user-friendly fashion. These files consist "NONMEM control stream". Nowadays almost all NONMEM models are based on input
files using NM-TRAN. Therefore in this document unless specified we
use "NM-TRAN control stream" and "NONMEM control stream"
interchangeably, to mean input files based on NM-TRAN syntax. See next
section and
@@html:<a href="/reference-manual/files/#nm_control_stream/">Reference Manual</a>@@
for details of the old NONMEM control input files.

[fn:2] With NONMEM 7.5, an additional file, FDATA.csv is produced that
outputs the contents of its input data file (typically FDATA) in a
comma delimited file format, so you can check how NONMEM interprets
the input data. The records in FDATA.csv may differ from those in
FDATA in the following cases. If REPL/REPL_ is used, the replicated
form of the data will appear in FDATA.csv.
